# The Trust Gradient

### Cognitive Load and Friction in Debugging AI-Generated Code

A UX research case study investigating how **AI-assisted coding changes developer cognition, trust, and debugging behavior**.

The study explores what happens when developers debug AI-generated code and how automation bias can shift—not necessarily reduce—the cognitive effort required to solve problems.

---

## Research Question

> How does AI-generated code affect cognitive load, trust, and debugging behavior?

The research focuses on the gap between **trusting an AI suggestion** and actually **understanding and verifying it**.

## Key Findings

### Phantom Familiarity

Developers can feel familiar with AI-generated code without fully understanding how it works.

### Automation Bias

Developers may place excessive trust in AI suggestions, reducing the amount of critical verification performed.

### Cognitive Load Relocation

AI assistance doesn't necessarily eliminate cognitive effort—it can shift the effort from writing code toward **reviewing, validating, and understanding generated code**.

### AI Trust vs Behavioral Trust

Developers may report trusting AI while their actual debugging behavior reveals a more complex relationship with that trust.

---

## Design Recommendations

The research translates the findings into interface-level recommendations:

### Risk-Based AI Highlighting

Make potentially risky AI-generated suggestions more visually prominent so developers know where additional verification may be necessary.

### Mandatory Review Pause

Introduce deliberate moments that encourage developers to review AI-generated code before accepting it.

### AI-Origin Indicators

Use visual indicators in the code editor to clearly communicate which code originated from AI assistance.
